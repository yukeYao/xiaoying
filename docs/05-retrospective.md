## 最难的问题

（作者填写）

可参考的事实：
- 文档冲突的处理贯穿了 v1 到 v4 四轮迭代：C03 / C04 在 v1 2/3，v2、v3 降到 0–1/3，v4 才变为 3/3。
- 只读片段导致冲突误判：v1 中模型总是用 paragraph_ids 只读命中段落，看不到写在其他段落的优先级（D05 P3）、废止说明（D07 P1）。
- 看到全文不等于会核对：v2 让 read_doc 返回全文后，gpt-4o-mini 的 C05 / C06 仍是 0/3。
- prompt 约束不住：v3 中 prompt 明确写了"不得并列矛盾规定""版本日期更新不代表优先"，两个模型仍然并列矛盾规定，或只取较新的一份。
- 更强的模型不等于更好：gpt-4.1 冲突识别更准，但过度核实循环导致总通过率低于 gpt-4o-mini（v4：24/48 vs 41/48）。
- 自动评测的盲区：C14_run1 判为通过，但答案套用了无关文档的建议。

## 关键决策与取舍

（作者填写）

可参考的事实：
- prompt 约束失败后，改用结构化输出 + 证据校验（conflict_check）：模型在结构化字段里能标出 true_conflict，状态一致性校验把 status 改对了。
- 先换模型诊断（v2-strong），区分"能力问题"（C05 / C06）和"不是能力问题"（C03 / C04），再决定改 prompt 还是改结构。
- 数据设计本身也会出错：第一版 variant 让 V03 也出现冲突；variant_b 的 D05 标题写"差旅"、适用范围写"全部"，内部不一致，导致 V05 误判。
- 检索：同义词扩展在小语料下没有可测量的收益，选择如实记录并暂停调参，而不是改问题来证明它有用。
- 评测方法：temperature=0 下结果仍有波动，所以每个用例跑 3 次；每轮结果用 tag 保留，不覆盖之前的结果。

## 学习收获

（作者填写）

可参考的事实：
- 逐字校验只能证明引用存在，不能证明引用支持回答；程序也无法判断 claim / basis 的语义（v4-strong V05_run1 把适用范围说明当作 priority 的依据）。
- "API 层重试"和"工具失败由模型决策"是两件事。
- 剩余步数提示让 gpt-4o-mini 在最后一步 finish，但它没有遵守"连续失败 2 次后换方式"。
- AI 辅助过程中的错误（`git add -A` 误提交、shell heredoc 误执行、分析结论与 trace 不符）都是靠记录和复查发现的。
