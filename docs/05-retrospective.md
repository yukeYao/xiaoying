# 05 复盘

> 本文由作者本人编写。

以下是对该项目复盘内容的重新梳理与结构化组织，旨在让技术路径、核心决策、经验教训和后续规划更加清晰、易读：

## 一、 核心难点：文档冲突处理的四轮迭代

项目在处理文档冲突时遇到了严峻挑战，核心在于准确区分“范围分工”、“已被替代”与“真冲突”，避免盲目并列矛盾规定或单方面采信新版本。这一问题历经四轮迭代才得以突破：

1. v1（只读片段）： 模型每次仅读取命中的局部段落，错失全局的优先级条款与废止说明，导致表面冲突被误判为真冲突。

2. v2（全文检索）： 改为返回全文后，模型并未掌握核对能力。小模型（如 `gpt-4o-mini`）仍无法正确判断，而某些用例则直接将不同时期的多项规定错误并列。

3. v3（Prompt 约束）： 明确写入冲突核对步骤与“版本更新不代表优先”等规则，但双模型在关键测试集上依然失效，出现并列矛盾、盲目采信最新版本或凭空捏造分工的情况。

4. v4（引入结构化输出）： 在 `finish` 阶段增加 `conflict_check` 结构化校验。通过状态一致性校验，成功引导模型正确输出冲突状态，显著提升了小模型的准确率。

此外，更强的模型不一定带来更好的整体效果。`gpt-4.1` 在冲突识别的准确率上占优，但由于陷入过度核实循环导致大量任务未完成，综合通过率反而低于 `gpt-4o-mini`。

## 二、 关键决策与取舍

* 先诊断，再改动： 区分能力瓶颈与提示词失效。通过引入强模型进行对比测试（v2-strong），明确哪些是换模型可解决的能力问题，哪些是需要调整 Prompt 或架构的系统性问题。

* Prompt 维度受限时转向结构化设计： 当纯提示词无法规范模型行为时，及时调整输出结构（如在 `finish` 中加入严格的 `conflict_check`），利用程序校验来弥补大模型语义理解的偏差。

* 严守数据质量与评测标准： 坚持“修改不符的数据，而非放宽期望”；在检索调参收益不明显时果断保持默认值；采用 `temperature=0` 且多轮次（3次/用例）独立打标（`--tag`）的评测方法，确保实验结果的可对比性。

* 默认模型选型： 综合稳定性与通过率，最终将 `gpt-4o-mini` 定为默认模型（尽管其在特定子任务上存在盲区），并选择将已知限制公开写入文档，而非刻意隐藏。

## 三、 核心经验与技术收获

* 引用存在 $\neq$ 引用支持结论： 逐字校验可以拦截虚假引用，但无法阻止“引用的依据正确、但推导出的结论错误”的逻辑偏差。

* 自动评测的局限性： 自动评测主要覆盖状态与格式，许多深层次的内容错误、工具调用异常（如将工具失败误判为资料缺失）仍需依赖人工审核。

* 结构化校验优于盲目强调规则： 让大模型输出结构化判断，再由代码进行一致性校验，比在 Prompt 中反复强调约束更为可靠。

* “能看到”不等于“会用”： 即便提供了全文信息，小模型也常忽略全局的优先级和废止说明，且提示词中的行为约束（如“连续失败后换方式”）容易被大模型忽视。

* 代码与辅助开发反思： AI 辅助开发中容易引入隐蔽错误（如误提交、heredoc 误执行、环境配置编码问题等），必须依靠严格的复查机制和规则约束来纠正。

## 四、 下一步优化方向

1. 解决强模型的过度核实： 尝试放宽对已读文档的 `scope_quote` 强校验要求，降低 `gpt-4.1` 的未完成率。

2. 弥补小模型的盲区： 针对小模型对“已被替代”判断的持续失利，考虑在结构化校验中强制增加废止/替代检查步骤，或针对冲突类问题动态切换至更强模型。

3. 增强答案内容自检： 增加自动化逻辑检查，例如校验回答中的数值是否均出自引用依据、排查冲突判断与引用列表之间的逻辑矛盾。

4. 优化回答条件保留： 在提示词中增加约束，确保大模型在回答时完整保留原文的适用条件（如特定年限、前提背景）。

5. 检索与评测集扩充： 在语料扩大、引入干扰文档后重新评估同义词扩展与长文本读取方案；同时扩充目前偏小的测试集（当前仅 16 个用例），重点增加冲突类和域外问题的覆盖度。
